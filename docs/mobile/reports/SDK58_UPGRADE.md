## 6. The open item: 2 contract tests fail (pre-existing, time-of-day dependent)
- **Failing tests** (`tests/contract/home.contract.ts`): "the Home reads validate with zod and contain no field beyond the B3 golden shapes" (line 133) and "every workflow family returns a valid envelope; all 18 tool results parse; the model is the mock" (line 193). Exact failure: `unknownFields(briefing, golden['route.a.coach.briefing'].body)` returns `plan.unscheduled[].task_id`, `.score`, `.reason`, `.title` instead of `[]`. The zod validation itself passes; only the "no field beyond the golden shape" comparison fails.
- **Cause:** the recorded golden body has `plan.unscheduled = []`. The backend planner (`domain/coach/service.py:526`) starts today's free window at `max(work_start, now)`, so later in the day some seeded tasks no longer fit and appear in `unscheduled`, a field shape the golden never contained. The same clock effect changed the screenshots ("3 planned tasks" to "2").
- **Control:** the same suite on the SDK 57 commit `bf0213a` (clean clone, `npm ci`, expo 57.0.34) at the same time of day fails the **same two** tests with the identical diff. (A third control failure was my scratch layout, the kill-switch script path.) Earlier today (before about 10:30 UTC) the same suite passed 13/13 on a scratch SDK 58 tree with equivalent dependencies; the failure appeared once the day had advanced (the exact threshold time was not measured). The other 11 contract tests (all 6 auth tests, kill switch, idempotent replay, 429, revocation) pass on SDK 58 in the repository.
- **Not fixed.** A test-only change would resolve it (for example, compare the shapes of `unscheduled` items only when the golden has items, or pin the clock) but it is outside the approved scope. **Decision for you:** approve a small test-only follow-up, or leave it; the suite is expected to pass again early in the day (not measured), which is why it passed in my earlier scratch run.
