## 9. Limitations and known risks
1. **Not verified on a device or simulator.** Keychain accessibility, `expo-network` on iOS, `expo-device` model names, background/foreground behaviour and real app kills are covered only by test doubles (carry-forward 1/2/6).
2. **Redirect handling in React Native:** the client discards any redirect and any off-origin final URL, but RN's fetch may follow a redirect before the check, so an Authorization header could reach the redirect target. Acceptable only because approved backends are operator-owned and never redirect; needs on-device verification.
3. Option B (private Codespaces URL) differs from a real cellular device; certificate/ATS behaviour unverified.
4. The `expo-crypto` addition (above) needs your acknowledgement.
5. `/v1/me` and most other routes are untyped on the backend (client validates with zod); backend response typing is still needed before M8.3.
6. Idempotent replay depends on the backend keeping the key for the replay window; if it expires the session is treated as ended and the user re-enrols (safe, but a lost response then costs a re-enrolment).
7. Contract tests need Docker and the repository's `.env`; they are manual by decision.
8. Carry-forwards from M8.0 remain: device/simulator verification, native icon check, bundle ID, backend typing, the 20 moderate advisories, native install-script verification.
