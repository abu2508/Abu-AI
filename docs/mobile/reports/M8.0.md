# M8.0 report: mobile foundation

Scope approved: Expo SDK 57 + TypeScript 6 strict + Expo Router; original Bloom identity and domain icons; SF Symbols for generic glyphs; Hybrid
visual direction; System Default appearance with live Light/Dark and an optional manual override. **Offline demo mode with synthetic data only.**

## 1. What was built
- `mobile/` Expo app: four-tab shell (Home, Finance, Messages, Coach) with the persistent Abu orb centred in the tab bar opening the **Ask Abu** command-surface shell (demo only); Settings navigation (index, Appearance, About fully built; the other seven sections are explicit "later milestone" placeholders).
- Design system: semantic tokens (light and dark palettes), spacing/radius/type/motion scales, theme engine, components (Text, Screen, Card, Section, Row, Button, Chip, SegmentedControl, Banner, EmptyState, ListRow, Divider, SyntheticChip, ModelChip, DemoBanner, Icon wrapper, TabBar, ScreenHeader, AbuOrb), original BloomMark and Finance/Messaging/Coach icons.
- Appearance: `useColorScheme` subscription = live System Default; override (System/Light/Dark) persisted via the single AsyncStorage module; native chrome follows an explicit override.
- Identity: original Bloom artwork (`assets/brand/bloom.svg`), app icon light/dark/tinted, splash image, favicon (generated by `scripts/generate-assets.mjs`).
- Demo mode and fixtures: every screen reads `src/testing/fixtures` (all names "(demo)"); money is a string formatted via BigInt (`src/lib/money.ts`); the inbox fixture is typed with the **generated** `InboxItem` and obeys the backend privacy rule (unshared conversation: `last_message_intent` null).
- Typed API client generation: `npm run api:types` turns the backend's committed `openapi/openapi.json` into `src/api/generated/schema.d.ts` (committed; CI checks it is current). No client networking exists yet.
- Safety: `PRODUCTION_GATES_VERIFIED=false` compiled in; persistent "Synthetic data" chip on every screen; Finance/Messages demo banner; Settings > About lists the four gates as BLOCKED; backend URL allowlist built and tested (unused: there is no networking); jest setup makes any `fetch`/`XMLHttpRequest` throw.
- CI: `.github/workflows/mobile.yml` plus the scripts under `mobile/scripts/`.

Differences from the approved register (all within approved packages; reasons are findings, not preferences):
1. **Pulled forward from M8.2 because M8.0's scope needs them:** `react-native-svg` (Bloom + domain icons), `@react-native-async-storage/async-storage` (appearance override), `expo-symbols` (SF Symbols), `expo-system-ui`, `expo-splash-screen`. **Skia, Playwright, blur and haptics were NOT installed**; the orb uses React Native's built-in Animated API.
2. **`react-native-reanimated` 4.5.1, `react-native-worklets` 0.10.1, `react-native-gesture-handler` 2.32.0 installed in M8.0**: they are required peer dependencies of `expo-router` (`"*"` ranges). Left unpinned, npm resolved them to the newest releases (reanimated 4.8.0, worklets 0.14.0, gesture-handler 3.5.0), which are incompatible with React Native 0.86. They are pinned to the SDK-bundled versions; they are not used by app code yet. Same cause: `expo-font` was resolved to 58.x, so it is pinned to 57.0.4.
3. **`eslint-config-expo` removed.** It bundles an `eslint-plugin-react` that does not run on ESLint 10 (`context.getFilename is not a function`). Lint uses `typescript-eslint` + `eslint-plugin-react-hooks` + project rules. (The register already flagged this as a risk.)
4. **`overrides`:** (a) `decode-uri-component: 0.5.1` clears the high advisories reached through `expo-router` -> `query-string`; 0.5.x is ESM-only, so Jest transforms it (and `standard-navigation`, also ESM-only); Metro web and iOS bundling were verified to work with it. (b) `openapi-typescript`'s peer `typescript: ^5` is overridden to the root TypeScript 6.0.3 (generation verified working and deterministic).
5. New gate `check:sdk` (scripts/check-sdk-alignment.mjs) fails if any direct dependency or any top-level SDK package drifts from the Expo SDK's bundled versions.

## 6. Known issues and limitations
- **Web is an approximation of iOS.** SF Symbols do not render on web (text stand-ins appear for the gear and home glyphs); fonts differ. Nothing was run in an iOS Simulator or on a device (no macOS, and the Apple Developer decision is deferred). Live Dark/Light switching is proven by the unit/component tests and the browser run; a device check of the native `useColorScheme` path remains.
- App icon dark/tinted variants and the splash are configured in `app.json` but only validated by `expo config`; they need an EAS/Xcode build to confirm.
- The orb's animations are exercised only through the Reduce Motion screenshots and accessibility tests; moving frames and frame rate are unmeasured (to be reviewed in M8.2 on a device).
- Increase-Contrast palette variants are not implemented (the OS does not expose a simple signal in React Native); the standard palettes already meet AA.
- Typed responses: most backend routes return untyped JSON (`Any`), so the generated schema is precise only for routes with response models (for example the inbox). Finance/coach fixtures are hand-typed until the backend adds response models (recommend a small backend task before M8.3).
- The bundle ID `ai.abu.mobile.dev` is a placeholder; not registered anywhere.
- (Superseded by section 8: the workflow has now run on GitHub and passed.) Screenshots use system Playwright (not a project dependency); formal `@playwright/test` visual regression is M8.2.
- Nested ESLint 9 and other deprecated transitive packages appear in the tree (dev tooling).
