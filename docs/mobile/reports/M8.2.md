## 9. iPhone checklist you must execute (Windows machine + iPhone, Expo Go)
Full text with commands: `docs/mobile/REDIRECT_CANARY.md`. The canary uses fake credentials only and never contacts the Abu AI backend.
1. On Windows (PowerShell): Node 22; `cd <repo>\mobile`; `npm ci`.
2. Confirm the Wi-Fi profile is **Private** (`Get-NetConnectionProfile`) and note your private IPv4 (10.x, 172.16-31.x or 192.168.x). If it is Public, switch it, or stop.
3. Administrator PowerShell, open the ports for **Private only, local subnet only** (temporary):
   `New-NetFirewallRule -DisplayName "Abu AI redirect canary (temporary)" -Direction Inbound -Protocol TCP -LocalPort 8801,8802 -Profile Private -RemoteAddress LocalSubnet -Action Allow`
   (If a Node.js firewall prompt appears: Private networks only.)
4. Start the canary and leave it open: `node scripts/redirect-canary.js` (prints e.g. `http://192.168.1.20:8801`; it refuses non-private addresses; use `--host <private IP>` if needed). **No port forwarding, tunnel, VPN or Codespaces port.**
5. Second window: `npx expo start --lan` (not `--tunnel`).
6. iPhone on the same Wi-Fi: scan the QR with the Camera, open in Expo Go. The app starts in demo mode.
7. In the app: Settings > **Transport canary (debug)** > enter the address from step 4 > **Run canary (301, 302, 307, 308)**.
8. Read the result on the phone and the Windows console:
   - **PASS**: all four statuses PASS, `secondOriginReceived=false`, console `=== RESULT: PASS ===`, no `B RECEIVED` line.
   - **FAIL**: `B RECEIVED` appears; the transport follows redirects and is unsafe. Stop and tell me.
   - **INCONCLUSIVE**: canary not reached or no redirect observed (e.g. ATS blocking cleartext LAN HTTP, firewall, wrong Wi-Fi). Not a pass; fix and rerun.
