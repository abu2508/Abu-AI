# Environment configuration guide

Three environments, three configurations. Never share an `.env` between them.

| | development | staging | production |
|---|---|---|---|
| Purpose | local work, tests | rehearse the real deployment with **synthetic data only** | **not authorised** |
| `ABU_ENV` | `development` (default) | `staging` | `production` |
| Compose layers | `docker-compose.yml` (+ `docker-compose.dev.yml`) | base + `hardened` + `staging` | base + `hardened` + `production` |
| Reachable at | `127.0.0.1:8000` (API) | `https://localhost:8443` on the host loopback only (Caddy, self-signed) | ports 80/443 via Caddy; needs an owner-approved domain |
| Database roles | one role | owner + runtime | owner + runtime |
| Deployment guard | off | **on** (fails closed) | **on** (fails closed) |
| Test embedder | allowed | only with `ALLOW_TEST_EMBEDDER_IN_PRODUCTION=true` (a statement that the data is synthetic) | **refused** (gate G4) |
| JSON redacted logs | optional | required | required |
| OpenAPI schema route | optional (`openapi_mode`) | off (cannot be enabled) | off (cannot be enabled) |

## Variables the operator sets (`.env`, mode 600, git-ignored, never pasted anywhere)

Generated by `infrastructure/scripts/gen-secrets.sh` (`ABU_SPLIT_ROLES=1` adds the owner role). Never put values in
commits, tickets, chat or logs.

| Variable | Used by | Notes |
|---|---|---|
| `POSTGRES_ADMIN_USER` / `_PASSWORD` | `db` only | superuser; never given to the API |
| `APP_DB_NAME`, `APP_DB_USER`, `APP_DB_PASSWORD` | `db`, `api`, `admin`, `migrate` | the **runtime** role |
| `APP_DB_OWNER_USER`, `APP_DB_OWNER_PASSWORD` | `db` (init), `migrate` **only** | the **owner** role; absent from `api` and `admin` (tested) |
| `LITELLM_DB_*`, `LITELLM_MASTER_KEY` | `litellm`, `api` (master key) | the gateway has no provider keys |
| `JWT_SECRET`, `TOKEN_HASH_KEY` | `api`, `admin` | >= 32 characters, different from each other |
| `ALLOW_TEST_EMBEDDER_IN_PRODUCTION` | `api`, `admin` | `true` only in staging with synthetic data |
| `ABU_UID` | `api`, `admin` | owner of `secrets/memory-keyring.json` |
| `STAGING_HTTPS_PORT` | `caddy` (staging) | default 8443, loopback |
| `ABU_DOMAIN`, `ABU_ACME_EMAIL` | `caddy` (production) | **no default on purpose** |
| `DB_MEM_LIMIT`, `LITELLM_MEM_LIMIT`, `API_MEM_LIMIT` | resource limits | defaults 1g / 2g / 768m |

## Settings the layers fix (do not override)

`ABU_TRUSTED_PROXY_HOPS=1`, `ABU_CHECKPOINT_AUTO_SETUP=false`, `ABU_LOG_FORMAT=json`, `ABU_MEMORY_KEYRING_FILE=/run/secrets/memory_keyring`
(never an env key), `UVICORN_ACCESS_LOG=false`.

## What happens when something is missing or unsafe

In staging and production the container **refuses to start** and names the setting (never its value): missing database URL,
JWT/hash secrets (or equal), LiteLLM key, keyring file, an env-key `ABU_MEMORY_KEK`, `TRUSTED_PROXY_HOPS != 1`, the owner URL
present in the runtime environment, checkpoint auto-setup on, non-JSON logs, an unknown embedder, or (production) the test
embedder. Compose also refuses to render when owner credentials or (production) the domain are unset.
At startup it additionally verifies the database role is least-privilege. Tests: `tests/unit/test_deployment_guard.py`,
`tests/security/test_deployment_config.py`, `tests/integration/test_role_separation.py`.

`.env.example` documents every variable with placeholders only.
